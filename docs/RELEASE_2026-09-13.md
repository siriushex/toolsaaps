# Source Release: 2026-09-13

## Scope

This release synchronizes the current Android application, backend, tests, tools
and reproducible event-icon assets with the public main branch. Existing public
README files, screenshots and documentation are preserved. Private development
history, patient databases, diagnostic dumps, credentials and build output are
not part of the source snapshot.

The repository contains experimental diabetes-management software. Passing
software tests does not establish clinical safety or authorize unattended
therapy changes. No therapeutic command or clinical upload is part of release
verification.

## Server AI Activation

Settings provides one masked authorization-code field and an Activate action.
The connection manager supports interrupted-activation recovery and explicit
subscription checks. Subscription validity and analysis availability are separate
states. Personal API-provider settings remain independent.

Device credentials use a separate Android Keystore/AES-GCM namespace excluded
from backup. Requests are bound to the hardware-backed application key, not the
client IP. The backend identity factory implements challenge, completion,
refresh and status. Activation commits the code, device, session and subscription
atomically. Refresh preserves the original subscription expiry; bounded encrypted
receipts allow retry without extending access or rotating recovered credentials.

**This is not a live server-Codex release.** Production attestation roots,
release-signer policy, fresh revocation data, a privately provisioned stable
receipt key, deployment and contained Codex job transport remain release gates.
The bound identity factory reports inference unavailable. No real authorization
code, API key or medical payload is included in this repository.

## Runtime Publication

Accepted NORMAL and SENSITIVITY_SOURCE_CHANGE cycles invoke the widget callback; LOCAL_READ_ONLY does not.
Publication follows accepted Room read-back and final committed runtime state.
ISF/CR settings identity, snapshot cycle and forecast generation must agree;
latest-by-horizon rows alone are not an authoritative runtime snapshot.

## Verification

The historical shared TLS credential container is removed from application
assets. The current local Nightscout implementation uses a per-installation
identity. Old Git revisions and old APKs may still contain that legacy container;
removing it from this release does not rewrite history or revoke old copies.

Run from the repository root with JDK 17, Android SDK and backend dependencies:

```sh
cd android-app
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleUiTest :app:assembleUiTestAndroidTest :app:lintDebug --max-workers=2
```

```sh
cd backend
python -m pytest -q
```

Phone verification must use a signature-matched, data-preserving update. Keep a
private coherent database backup and the previously installed APK. Isolated UI
tests use fake state and have no therapy or network capability. USB installation
approval, real-device UI, migration and runtime verification are separate gates;
an APK build does not prove them.

Release evidence and known verification limits are recorded in `AI_NOTES.md`.
